总体学习进度

源码：cursor/plugins/pstack（MIT）。安装：Cursor 聊天里输入 /add-plugin pstack。

几个先记住的点：playbook 不是技能，是 /poteto-mode 按需加载的参考文件；prompt 写“目标 + 能判定的完成条件 + 想要的证据”，不要罗列技能；她认为整套东西里回报最高的是验证技能。

对照 calvingit/skills

分工：需求对齐参考 Matt 的 skills（grilling、wayfinding、to-spec 这条线）；执行和验证参考 pstack。我们的 skill 保持独立、原子，不合并，也不打包成大 skill；交叉只留在流程路由上。

pstack 的做法我们对应的东西怎么借鉴
/create-verification-skill 生成项目内 verify 技能setup 时生成仓库级 verify skill；全局 verify 只按那份配方跑对照它的 Feature Map 和“交付前先证明一次”，看我们 setup 生成的配方缺不缺这两样
/maintain-verification-skill 只出 clean / changed / blocked暂无对应的定期维护步骤可考虑给仓库级 verify skill 加一条定期自检，结果也限定成几种
Prove It Works、Sequence Verifiable Units独立 verify、PASS/FAIL/NOT VERIFIED、to-tickets / loop意思接近，不需要搬原则进 Kernel
/correct 按“结构优先”修反复出现的错Kernel、closeout-roles 偏契约反复出错时先想能不能变成检查脚本，而不是加一段文字
PR #538 的压缩方法我们 Phase A/B 的去复述只用在从 pstack 搬来、还偏长的 skill 上
/ketchup 汇报格式无可作为一个独立小 skill 参考，不塞进现有 skill
原则索引（偏手艺）Kernel / task-contract（偏契约）不是一一对应，各管各的

不学的：一个入口带 23 个 playbook 的大 mode 形态。和我们“skill 原子、各自独立”的做法相反，看懂思路就行，不照搬结构。
